## Production recipe

Use the retained authenticated environment, including the matching Python
library. The unqualified host Python executable/library combination has an
internal ABI mismatch. This changes no compiler toolchain selection:

```sh
export PATH="$HOME/Workspace/codex/work/astra/runtime/selfhost27c-entry2/pinned-bin:/usr/local/bin:/usr/bin"
export LD_LIBRARY_PATH="$HOME/Workspace/codex/work/astra/runtime/selfhost27c-entry2/pinned-lib"
export LIBRARY_PATH="$LD_LIBRARY_PATH"
export LC_ALL=C.UTF-8
python3 -B tests/selfhost-convergence-27d/run.py generate --stage 1
python3 -B tests/selfhost-convergence-27d/run.py observe --stage 1
python3 -B tests/selfhost-convergence-27d/run.py regress --stage 1 --mode O2
python3 -B tests/selfhost-convergence-27d/run.py regress --stage 1 --mode O0
```

The running first generation must be joined, not started twice. Repeat generation
and observation for stages two and three, using the previous stage's actual O2
compiler as producer. Each generation independently builds O0 and O2 compiler
hosts into new destinations; both profiles consume F. O0 companions receive
target O0/O2 qualification, while O2 hosts produce the next generation. A target
optimization flag is not reported as a compiler-host profile.

Seven existing C provider objects are authenticated caches from byte-identical
F. Their original source snapshots, complete GCC dependency hashes and tool
identities are checked; no cached Astra compiler object or executable supplies a
new generation. Actual production `astrac -c` emits each compiler object. The
ordinary C linker links it with those provider objects and LLVM. The live
producer's executable, argument vector, input order, mapped LLVM library and
absence of process-launch imports are independently observed through `/proc`.
Every compile retains stdout, stderr, exact exit, wall/user/system time and RSS.

The unmodified existing acceleration runner controls isolated regression jobs,
with four workers, an 8 GiB memory reserve, and no artifact reuse. Its three
context imports resolve through this tracked recipe, avoiding the protected
untracked legacy `run.py`. The existing 27-B/27-C recipes retain their own
source, LLVM, native, negative, physical and strict memory assertions. The C
client and application wrappers are parameterized versions of retained 27-C
invocations; they preserve the explicit private-fastcc/C-descriptor bridge and
the original application expectations, I/O faults and malformed-argv controls.

Compiler objects and ELF products are compared byte-for-byte for Stage1/2 and
Stage2/3. Stage2/3 corpus LLVM, object and ELF products are also compared exactly.
Diagnostic comparisons replace only the declared generation output roots;
offsets and remaining message bytes stay exact. Valgrind process-statistics
lines are excluded from diagnostic comparison only after independently checking
zero errors, zero live bytes and zero suppressions. Raw streams and differences
are preserved. No normalization grants byte identity to different artifacts.
