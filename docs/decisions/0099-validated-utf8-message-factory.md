## Approved design comparison (written before implementation)

1. **Ordinary library-only factory (preferred in principle): unavailable at
   this baseline.** A free `owned Utf8Message` function with checked throws is
   legal, but it cannot produce StringType from u8[]. A user-written validator
   returning bool supplies no certified text origin. A constructor cannot throw.
   Casting, pretending a borrowed result is static, or an external C factory
   would bypass the required source boundary.
2. **Recommended bounded option: one explicitly annotated native factory**,
   with ordinary library-defined owner and error Classes. Add exactly this
   opt-in library at `lib/astra/text/utf8-message.astra`:

   ```astra
   class Utf8Message {
       readonly string snapshot;
       init(string input) { this.snapshot = input; }
       property string text { get { return this.snapshot; } }
   }
   class InvalidUtf8 : Error {
       init() : base("invalid UTF-8") {}
   }
   [Utf8MessageFactory]
   owned Utf8Message utf8_message(u8[] bytes) throws InvalidUtf8;
   ```

   **At the approval baseline, the annotation and bodyless native definition
   were proposed new syntax and unsupported.** The annotation gives compiler authority to one
   exact factory declaration; names alone never certify a user Class or text.
   This is one compiler intrinsic supplied through an explicitly selected
   library, not a library-only implementation, foreign declaration, general
   intrinsic registration system or static-method feature. Ordinary unannotated
   native declarations still require bodies. No implicit default library load.
   `Error` must resolve to the selected ordinary nominated ExceptionRoot;
   applications select the existing errors source or their compatible root.
   No exception root or privileged user Class is synthesized by spelling.

   Validate the exact unique declaration, non-generic synchronous signature,
   borrowed u8[] input, heap owned result, nominated checked error ancestry,
   single readonly snapshot field, canonical string-copy constructor, pure
   receiver getter, and static-diagnostic no-arg error constructor. Initially
   admit only these canonical Class shapes, with no inheritance/extra members
   on the message or effectful/custom construction. Reject malformed nominations
   and duplicate factories. All referenced declarations have ordinary nominal
   identities copied into each phase's own contract.

   Caller shape (prospective, not a baseline compiling example):

   ```astra
   u8[5] bytes = {99, 97, 102, 195, 169};
   try {
       var message = utf8_message(slice(bytes));
       { var view = message.text; /* existing string consumers here */ }
       release message;
   } catch (InvalidUtf8 error) {
       /* error.message == "invalid UTF-8" */
   }
   ```

   The ordinary string constructor remains useful and safe for already-valid
   strings. Byte construction is available only through the annotated factory.
   A fresh named owner receives the result; implicit bytes-to-string assignment,
   inline owner passing and discarded owned results keep their current rules.
3. **Hold** for a broader design/ABI review. If implementation cannot maintain
   the contract below, return here for a new decision; do not broaden it silently.

## Length, validation, publication and failure

The finite byte bound is **0..2,147,483,647**, the existing nonnegative I32
slice/text count. Borrow an actual legal native u8[] synchronously; never retain
its descriptor or payload. Check count and the nonempty/non-null base relation
before any load; do not dereference a zero-count view. Legal slice construction
and existing call provenance supply readable extent, not the UTF-8 validator.
No runtime pointer check can certify an arbitrary forged pointer's readable
allocation. Lower-stage origin/count corruption must be rejected by verifier
contracts, rather than claimed as an accepted source/foreign ingress route.

Validate the complete input **before allocating a message**. The private LLVM
validator uses exact input base/count, checks remaining bytes by subtraction
before lookahead, and never forms an overflowing I32 index. Accept U+0000,
ASCII, canonical two/three/four-byte scalars, combining sequences, noncharacters
and empty input. Reject stray continuations, C0/C1, F5–FF, truncated sequences,
invalid continuations, overlong encodings, surrogates and values above U+10FFFF.
No normalization, locale, sentinel, scalar count or grapheme policy is added.

On valid input, use a certified internal bounded view solely to call the exact
canonical constructor, which immediately copies to its existing readonly
snapshot. There is no source-visible byte-to-borrowed-string operation. No
callback, user mutation, async suspension or retained caller alias intervenes
between validation and copy. Publish the complete heap owner only after that
copy. Empty payload may be `{null,0}` inside a separately allocated non-null
message; equal empty messages are still distinct owners. No NUL terminator is
required, and embedded NUL is retained by exact counted copy and equality.

On invalid input, construct and throw one ordinary InvalidUtf8 with diagnostic
content `invalid UTF-8`, no byte excerpt or offset. No message or temporary
snapshot has been allocated on this branch. The existing Error root copies its
static diagnostic into an ordinary owned snapshot: static diagnostic **content**
does not mean allocation-free error delivery. Catch/propagation uses ERROR-1
cleanup. Existing unrelated owners and caller bytes remain intact. There is no
checked failure after message allocation; allocator exhaustion at any success or
error allocation remains **fatal, noncatchable and without unwind guarantees**.

Visible cost is linear validation plus an independent counted copy (and the
existing allocator's zero initialization), one Class lifetime and payload
cleanup. Source/lowering predicts one object allocation plus one nonempty
payload allocation on success, and the ordinary error object/payload path on
failure. Instrument these counts before claiming measured allocation behavior.
No refcount, registry, pool, new allocator or external validator dependency.

## Phase and lifetime obligations before implementation can pass

These are proposed checks to implement and falsify, **not existing byte-ingress
proofs**. Reusing a trusted text-origin leaf alone is insufficient.

| Gate | Required independent authority |
| --- | --- |
| Checked | Resolve annotated definition and exact Classes/constructors/error effect; u8[] retains its normal noescape origin and complete count. Factory result owns the exact heap Class. No arbitrary bool or cast can certify text. |
| Core | Dedicated validated-construction contract retains input group, exact result/error/constructor/field identities and validate-before-copy order. Verify those against the actual definitions, not a copied trusted flag. Unapproved generic/foreign/async uses reject. |
| CFG | Retain a dedicated validation/publish relation with success/failure successors. Validity belongs to the exact base/count group; only the valid edge can enter snapshot construction. Error edge never reads/publishes success storage. Rebuild acquisition/transfer/cleanup obligations. |
| SSA | Check exact paired input definitions, domination of certified-view use by validation, unchanged input through the canonical constructor, complete owner acquisition/disarm and success/error edge correlation. Removing or swapping validity/count/owner evidence must reject. |
| Native/LLVM | Preserve byte-slice vs NativeTextType identities despite shared PTR/I32 carriers; verify the factory against SSA and its exact native Class/error plan. Check validator loads/bounds/branches, canonical copy call, success storage and cleanup bindings against actual emitted instructions. A plain LLVM verifier pass is insufficient. |

The internal certified view may exist only on the valid branch for the one
immediate canonical copy call. It is bounded by the still-live byte input,
never static, independently owned or returned. After copying, the public
`.text` result uses the existing RECEIVER_TEXT contract rooted in the message's
snapshot. Its owner/extent flows through local copies and joins; returning,
outer-scope storage, release, move or replacement while a loan survives must
reject through the actual loan authority. Ending the inner scope permits later
owner release. A concrete child field owns the message and invokes its existing
payload cleanup followed by heap free exactly once. No collection/generic
storage rule changes. Forged lower-stage receiver association and cleanup
disarm must independently reject with restoration.

The physical factory can keep the existing private checked ABI: exception PTR
return, private owned-success PTR slot, borrowed bytes PTR/I32 components.
Message storage remains the ordinary readonly snapshot Class shape. No public
StringType, foreign text or allocator ABI changes are proposed. Emit the private
UTF-8 helper only for programs actually using the facility, and compare unused
program dependencies/symbols. All future native/O2, malformed, mutation,
allocation-observer, child/early/checked cleanup and unsuppressed memory results
remain required by the submission; none is inferred from this design baseline.
