# Application integration and focused qualification

The indexer now has a multi-file async CLI implementing the original TSV format.
Every request can suspend in the opaque middle library. One owned cache and
checked closure environment persist across requests; argument snapshots have
independent owners, including paths not reached before cancellation. The original
single-file prototype is retained. The async batch default processes malformed or
missing files as error rows and continues to later inputs.

Completion, cold cancellation, suspension cancellation and cancellation after the
first document require exact argument construction/retirement counts. Dynamic
policy dispatch still executes consumer-defined behavior before creating the
owned classification table. Virtual timers and real Linux io_uring timers are
separately linked profiles. File transfer remains the explicit synchronous POSIX
adapter; this is not a claim of asynchronous file reads.

The optional read-fault transport delegates to the real adapter and fails once
after seven bytes. Astra must discard the partial document, continue to another
file, and retry the original through the same live callback environment. Exact
oracle output, callback/cache counters, zero memory losses/errors and no extra
open descriptors are required. Default application builds exclude the fault
adapter. A representative public staged O1 build without it was separately run.

The opaque producer exposed an incidental native profile gate: owning slot fields
were admitted only when the containing Class was generic. That gate now accepts
ordinary Classes through the same independently verified field layout, nominal
element and cleanup authorities. No fixture recognition or schema change was
introduced. Box, Map and Cache are now installed with the ordinary standard
library, allowing the full application to build outside the repository.

The reconciliation challenge was implemented after its requirements, wire schema,
Python reference and inputs were frozen in Git. Inventory<K,V,Context> stores an
independent copied key, copied stock, owned bookkeeping context and revision;
its independent project<R> method transports typed snapshots. A checked closure
receives copied proposals and returns copied receipts across the opaque native
boundary. Checked audit failures transport their counters and leave stock and
revision unchanged; retry reuses the same owned environment. Invalid changes do
not call the audit. Signed arithmetic and input prefixes are checked. Final
inventories are independently sorted by their two-part keys.

Its renamed/reordered source variant changes actual declaration/field identities
and field order while preserving protocol strings. Both variants run all three
precommitted input sets, including 24 changes per set, plus invalid input and
partial-initialization cleanup controls. Lifetime-only C observers count owned
contexts; all reconciliation, arithmetic, callback decisions and output are Astra.

Ordinary owned closures may enter existing single-threaded task frames; borrowed,
actor, threaded and Shared/Weak captures remain rejected. Each IR checks the
capture rule independently. Native frame ownership retains the callable type,
typed environment destructor and allocator, including cancellation. Borrowed
interfaces are sampled into an owned classification table before suspension.

The maintained recipes are `tests/file-indexer-15` and `tests/reconciliation-15`.
Their matrices retain monolithic O0/O1/O2, mixed native-unit optimization levels,
hidden producer sources, installed standard-library consumers and independent
application/ownership oracles. A recipe or a historical result does not qualify
a new compiler; record actual current profile results separately.
