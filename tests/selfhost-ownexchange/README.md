# OWNEXCHANGE-19 qualification recipes

The installed `pm-next` intake owns the submission identity. These recipes run
inside the existing Astra checkout; they do not replace intake or publication.
`state.py` pins the initial HEAD/tree, report, C0 binary, protected files and donor,
and re-executes the exact predecessor source-ledger commands before edits.

All task products belong under `~/Workspace/codex/work/astra/build/ownexchange19/`.
Evidence belongs under the corresponding `runtime/ownexchange19/`. Source freezes
are explicit copies of tracked inputs, with per-file SHA-256 inventories. Native
builds use `tests/selfhost-llvm/build.py --source-root FREEZE --build OUTPUT
--runtime EVIDENCE --mode O0|O2 --compiler C0`. Both this recipe and every linked
source/tool/provider are part of its product identity. Use a new leaf after an
input change; retain failed and interrupted receipts. An exact warm cache hit is
product reuse, never a fresh test result.

`corpus.py`, `family.py`, `twins.py` and `extra.py` freeze independent C0/manual
oracles. The first includes a source view retaining the byte-exact complete
`FlowGraph.add` body and `room` method, with explicitly reduced Class storage and
disclosed syntax-ID/capacity dependencies. The six family views retain original
record declarations and individual exchange operations in disclosed growth
wrappers; they do not qualify their complete original methods. Every executable
source identity has its own source, binary, outcome and memory receipts.

`qualify.py --component PRODUCT --mode O0|O2 --name UNIQUE-LEAF --gate GATE`
runs `new`, `family`, `twins`, `extras`, `mutations`, `resource`,
`inherited-native`, `inherited-text` and `inherited-indexpath` separately.
Inherited commands and source selections come from the exact INDEXPATH-18
receipts. No test PASS is imported from those receipts. `resource` retains the
complete original `CfgWalk.inspect` SSA deferral at the unchanged limit.

`faults.py` records source refusals at their actual stages, plus accepted twins
and object preservation. Persistent slice declarations already violate C0's
escape policy; they do not prove detection of a surviving legal borrow. The
pending-argument controls exercise actual temporary loans and containing-object
aliases. `lifetime.py` links test-only libc observers, checks allocation identities
and cleanup order against C0, and separates fatal/no-unwind observations from
normal-exit unsuppressed Valgrind checks. The observer implements no exchange.

The dedicated Astra mutation harness checks Core/Flow metadata, owner facts,
cleanup order, CFG continuations and SSA refinement, then creates LLVM-valid wrong
loads/stores, partial descriptors, premature stores, extra free effects and null
receiver addresses. Valid and restored twins remain accepted. Rejected mutants
must preserve previously qualified object and ELF bytes.

`frontend.py` is a diagnostic source-ledger consumer, not a native qualification.
`cohorts.py` compares exact source/node/span identities and actual checked stops
for all four frozen populations. Final-live observations are separate.
`witness.py` binds original bytes and independently parsed C0 method syntax to
Core/CFG/SSA and native/C0/Valgrind receipts. `audit.py` checks preservation;
`costs.py` reports actual intervals, CPU/RSS, overlap and exact reuse. Historical
OWN-SWAP and the 1,044 inherited proof records retain their original attribution.

The first final O0 family run retained five successful views and one private-name
resource refusal. `family-v3` places the disclosed wrapper beside the unchanged
original operation, preserving its byte offset and record declarations while
avoiding thousands of blank bytes inside the Class source span. The first
lifetime run retained normal and failed-replacement observations, then exposed
the existing Core refusal of a local null initializer. Repaired guard witnesses
pass null through an already admitted borrowed Class parameter. Final receipts
use `family-repaired` and `lifetime-repaired` leaves; failed leaves remain intact.
Neither repair changes the final compiler or broadens source admission.

After all gates, `summary.py` checks the complete execution closure;
`correspondence.py` binds compiled sources and changed bytes to final Git blobs.
`handoff.py` verifies lossless evidence transport for the installed publisher.

Only the unchanged installed publisher may replace `astra-report-current.zip`.
No recipe authorizes donor writes, history changes, a push, release, public ABI
expansion, a larger SSA budget or a Stage 1 claim.
